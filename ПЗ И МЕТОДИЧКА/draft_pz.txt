АННОТАЦИЯ

Курсовой проект на тему «Система для организации киберспортивных турниров» состоит из программного средства, пояснительной записки и графической части.
Данное программное средство предназначено для автоматизации процессов проведения и администрирования киберспортивных соревнований.

Пояснительная записка выполнена на 89 листах, содержит четыре раздела и одно приложение.
Графическая часть выполнена на двух листах, включает диаграмму вариантов использования и диаграмму последовательности.

ВВЕДЕНИЕ

Разработка специализированной информационной системы для автоматизации процессов организации и проведения киберспортивных турниров является актуальной и востребованной задачей в условиях стремительного роста индустрии цифровых соревнований. Эффективная программная реализация процедур регистрации участников, автоматического планирования игровых сеток и ведения статистики в реальном времени напрямую влияет на прозрачность состязаний и общую производительность платформы. В связи с этим внедрение комплексной системы управления данными позволит значительно упростить администрирование мероприятий, обработку результатов матчей и повысить качество взаимодействия между организаторами и игровым сообществом.
Многие организаторы киберспортивных соревнований по-прежнему используют устаревшие и зачастую ручные методы ведения учета данных и администрирования, что неизбежно приводит к неоправданному увеличению времени на обработку заявок и существенному повышению вероятности возникновения критических ошибок при фиксации игровых результатов. В условиях стремительного развития индустрии и нарастающей конкуренции между игровыми платформами, внедрение современных автоматизированных решений становится технологической необходимостью для обеспечения высокого качества сервиса, прозрачности состязательных процессов и значительного повышения общей эффективности работы всей системы.
Целью данного курсового проекта является разработка программного комплекса и базы данных, предназначенных для надежного хранения и эффективной обработки информации о пользователях, игровых командах, турнирных заявках и результатах матчей. В ходе работы будет выполнен детальный анализ имеющихся рыночных решений, рассмотрены их преимущества и технические недостатки, что в итоге позволит выделить и обосновать уникальные функциональные особенности проектируемой системы управления турнирами.
Проект направлен на автоматизацию процессов организации киберспортивных соревнований с целью упрощения процедур администрирования, учета участников и оперативного обслуживания аудитории. Основные задачи работы включают:
систематизацию полученных знаний: Обобщение теоретических аспектов, связанных с управлением большими массивами данных в сфере цифрового спорта и соревновательных дисциплин;
углубление уровня и расширение объема профессионально значимых знаний: Детальное изучение современных объектно-ориентированных и архитектурных подходов к проектированию реляционных баз данных и их эффективному применению в высоконагруженной индустрии гейминга;
формирование умений и навыков самостоятельной работы: Разработка и развитие практических компетенций по созданию, отладке и комплексному внедрению распределенных информационных систем на базе современного стека технологий (C# и Python);
овладение современными методами поиска, обработки и использования информации: Изучение передовых технологий интеграции внешних программных интерфейсов (API PandaScore), методов синхронизации данных в реальном времени и их связки с динамическими пользовательскими интерфейсами;
Пояснительная записка включает следующие разделы:
назначение и область применения: Описание назначение разработанной программы и характеристика области применения. Анализ предметной области, включая особенности работы киберспортивной системы и потребности в автоматизации, а также обзор существующих решений, их достоинств и недостатков.

Приводится аналитический обзор существующих программных подходов к решению задач турнирного администрирования, рассматриваются их достоинства и критические недостатки. Особое внимание уделяется описанию уникальных отличий разработанной программы от рыночных аналогов, таких как автоматизация генерации сеток и интеграция с внешними API данными. «Тестирование и анализ полученных результатов». Описывается проверка работы программы на различных тестах и приводится анализ ожидаемых и полученных результатов, выводы по результатам тестирования.
«Руководство по использованию программного средства» – описывается последовательность действий пользователя, обеспечивающих загрузку, запуск, выполнение и завершение программы, приведены описание функций, формата и возможных вариантов команд, с помощью которых пользователь управляет выполнением программы, а также ответы программы на эти команды.
НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ

Эффективная организация процессов проведения и администрирования киберспортивных турниров является ключевым фактором для обеспечения их успешного функционирования и дальнейшего масштабирования игровой платформы. В условиях стремительного роста популярности цифровых соревновательных дисциплин и постоянного увеличения числа активных участников, комплексная автоматизация всех этапов управления становится неотъемлемой частью современной соревновательной индустрии. Многие организаторы мероприятий до сих пор сталкиваются с серьезными системными трудностями, вызванными отсутствием единых профильных автоматизированных систем, что неизбежно приводит к значительным временным задержкам при формировании турнирных сеток и снижению общего уровня качества взаимодействия с игровым сообществом.
В настоящее время значительная часть ключевых операций, таких как регистрация командных заявок, формирование турнирных сеток и фиксация результатов игровых встреч, выполняется в ручном режиме, что создает серьезные предпосылки для возникновения ошибок человеческого фактора и затрудняет оперативное информирование участников о текущем ходе соревнований. При администрировании турнирного процесса необходимо учитывать множество критических факторов, таких как статус подтверждения участия команд, их актуальные рейтинговые показатели для корректного посева в сетке, а также специфические правила проведения конкретных этапов выбранной дисциплины.
С внедрением информационной системы для управления киберспортивными турнирами процессы организации соревнований значительно упростятся. Автоматизация позволит существенно сократить временные затраты на регистрацию участников, формирование турнирных сеток и оперативное взаимодействие с игровым сообществом. Администраторы и судьи смогут полноценно взаимодействовать с программным комплексом непосредственно на своих рабочих местах, что значительно повысит эффективность координации матчей и качественно улучшит опыт взаимодействия для всех категорий пользователей.

Постановка задачи

Функциональные требования к администратору заключаются во внедрении возможностей добавления новых турниров в базу данных. Реализовать для администратора возможность вносить новые мероприятия, включая название, дату проведения и дисциплину. Разработать функции редактирования информации о существующих турнирах, что позволяет обновлять расписание или список участников. Важно предусмотреть возможность удаления турниров из базы данных, если они больше не планируются к проведению.
Для обычного игрока реализовать доступ к текущему списку соревнований, что позволит видеть подробную информацию о каждом турнире. Внедрить возможность просмотра сведений об участниках, включая никнейм, текущий рейтинг и игровую статистику. Реализовать функции подачи и отзыва заявок на участие в турнирах, что обеспечивает актуальность списков игроков и упрощает процесс формирования турнирных сеток.

Описание программных средств 

Проект представляет собой распределенную систему, состоящую из веб-приложения на Django и серверного API на платформе .NET 8.0, предназначенную для автоматизации управления киберспортивными турнирами.
Стек технологий объединяет в себе возможности ASP.NET Core для разработки серверной логики, Entity Framework Core для управления данными и SignalR для обеспечения обновлений в реальном времени. Взаимодействие между фронтендом и бэкендом осуществляется через RESTful API, что позволяет эффективно разделять задачи обработки данных и их визуализации. Использование готовых библиотек Django и компонентов Bootstrap 5 значительно ускоряет проектирование интерфейса. 
Система включает в себя инструменты интеграции с внешними сервисами, такими как PandaScore и Faceit, что делает процесс управления участниками и статистикой автоматизированным и визуально наглядным. 
Программный комплекс изначально спроектирован с использованием контейнеризации Docker, что обеспечивает его полную кроссплатформенность и стабильную работу в средах Windows и Linux.
Архитектура решения построена на разделении ответственности: C# бэкенд отвечает за сложные вычисления и интеграции, в то время как Django фронтенд обеспечивает удобное взаимодействие с пользователем. Использование Redis в качестве промежуточного слоя позволяет оптимизировать производительность и кешировать запросы к внешним API. Данный набор технологий представляет собой современный комплект инструментов, обеспечивающий высокую масштабируемость и надежность системы управления турнирами.

Проектирование интерфейса

Данный курсовой проект состоит из элементов управления для навигации по приложению и нескольких форм, которые содержат в себе соответствующую им информацию.
Вкладка регистрации, которая отображается при переходе пользователя к созданию новой учетной записи, рис. 2.1., содержит следующие элементы:
поле ввода ника – поле для ввода игрового псевдонима пользователя;
 поле ввода электронной почты – поле для ввода адреса почтового ящика пользователя;
поле ввода пароля – поле для ввода секретной комбинации символов, которая должна содержать не менее 8 знаков;
выпадающий список выбора роли – элемент для выбора типа профиля: капитан, игрок;
кнопка создания аккаунта – кнопка для завершения процесса регистрации и отправки данных в систему;
кнопка входа в аккаунт – кнопка-ссылка для перехода к форме авторизации, если у пользователя уже есть профиль.

 
Рис. 2.1. Страница регистрации

Вкладка авторизации, рис. 2.2., содержит следующие элементы:
поле ввода электронной почты – поле для ввода адреса почтового ящика пользователя;
поле ввода пароля – поле для ввода пароля;

Рис. 2.2. Страница авторизации

кнопка открытия списка турниров – кнопка для перехода к разделу с полным перечнем доступных турнирных мероприятий;
панель отображения количества зрителей – элемент для демонстрации суммарного охвата аудитории платформы;
панель отображения количества событий – элемент, информирующий о количестве запланированных или проходящих мероприятий на текущую дату.

 
Рис. 2.3. Главная страница

Вкладка Турниры, которая отображается при переходе пользователя в раздел управления соревнованиями, рис. 2.4., содержит следующие элементы:
поле ввода названия турнира – поле для ввода наименования проводимого мероприятия;
поле ввода названия дисциплины – поле для указания игровой дисциплины турнира;
поле ввода призового фонда – поле для ввода суммы общего призового фонда соревнований;
поле ввода количества участников – поле для установки максимально допустимого числа команд или игроков в турнире;
поле ввода даты старта турнира – поле для выбора календарной даты начала соревнований;
выпадающий список формата турнира – элемент для выбора системы проведения турнира (например, олимпийская система или групповой этап);
выпадающий список типа этапа турнира – элемент для определения структуры сетки соревнований;
кнопка создания турнира – кнопка для подтверждения создания и сохранения нового турнира в системе;

ЗАКЛЮЧЕНИЕ 

В ходе разработки дипломного проекта по программированию на тему «Платформа для автоматизации и проведения киберспортивных турниров» были выполнены следующие этапы:
Проведен анализ существующих систем турнирного менеджмента и киберспортивных платформ, выявлены их архитектурные и функциональные недостатки.
Разработана гибридная микросервисная архитектура приложения, разделенная на бэкенд-ядро (REST API) и тонкий клиентский слой (SSR), а также определены ключевые интеграционные модули и инструменты для реализации необходимых функций.
Написан программный код бэкенда на платформе .NET 8 (ASP.NET Core / Entity Framework Core) и фронтенда на языке Python с использованием фреймворка Django 4.2. Реализованы модули управления командами, автоматической генерации турнирных сеток, реалтайм-обновления матчей, голосования за MVP и интеграции с внешними API.
Проведены комплексное тестирование (включая проверку ролевой модели доступа) и сквозная отладка взаимодействия контейнеров приложения для обеспечения стабильной и корректной работы.
Для пользователя реализованы следующие функции:
возможность авторизации и динамического разделения прав доступа в зависимости от роли (администратор, судья, капитан, игрок);
возможность создания киберспортивных команд, управления их составами, добавления игроков и подтверждения их игрового рейтинга;
возможность автоматической генерации Single Elimination сетки турнира на основе верифицированных и подтвержденных заявок от команд;
возможность поиска турниров по названию и фильтрации матчей по их текущему статусу (запланирован, идет трансляция, завершен);
возможность отслеживания результатов матчей, счета и игровых событий в режиме реального времени без перезагрузки страниц на базе протокола SignalR;
возможность бесшовного переключения цветовой палитры интерфейса (светлая или тёмная тема) с плавными визуальными эффектами.
возможность интерактивного голосования за лучших игроков турнира (MVP) с защитой от повторных голосов;
В результате работы была создана полноценная киберспортивная платформа, которая автоматизирует весь цикл проведения соревнований: от подачи заявок командами до распределения призового фонда и выгрузки аналитических отчетов. Архитектура проекта изолирована с помощью контейнеризации Docker Compose, оркеструющей работу серверов API, веб-приложения Django, СУБД PostgreSQL, кэширования Redis и прокси-сервера Nginx, что гарантирует высокую отказоустойчивость, безопасность персональных данных и масштабируемость системы.

    } catch (...) {

    TADOQuery *checkQuery = new TADOQuery(NULL);

void __fastcall TForm11::ButtonConfirmClick(TObject *Sender)
{
if (ListBox1->Items->Count == 0) {
        ShowMessage("Сначала добавьте товары в заказ.");
        return;
    }

    double totalSum = 0.0;

    for (int i = 0; i < ListBox1->Items->Count; i++) {
        String item = ListBox1->Items->Strings[i];
        int pos1 = item.Pos(" (x");
        int pos2 = item.Pos(")");
        String name = item.SubString(1, pos1 - 1);
        int quantity = StrToInt(item.SubString(pos1 + 3, pos2 - pos1 - 3));

        TADOQuery *priceQuery = new TADOQuery(NULL);
        priceQuery->Connection = ADOQuery1->Connection;
        priceQuery->SQL->Text = "SELECT price_ FROM coffee WHERE name_ = :name";
        priceQuery->Parameters->ParamByName("name")->Value = name;
        priceQuery->Open();
        double price = priceQuery->FieldByName("price_")->AsFloat;
        totalSum += price * quantity;

        TADOQuery *updateQuery = new TADOQuery(NULL);
        updateQuery->Connection = ADOConnection1;
        updateQuery->SQL->Text = "UPDATE coffee SET count_ = count_ - :qty WHERE name_ = :name";
        updateQuery->Parameters->ParamByName("qty")->Value = quantity;
        updateQuery->Parameters->ParamByName("name")->Value = name;
        updateQuery->ExecSQL();
        delete updateQuery;
        delete priceQuery;
    }

    String zakazText = "";
    for (int i = 0; i < ListBox1->Items->Count; i++) {
        zakazText += ListBox1->Items->Strings[i];
        if (i < ListBox1->Items->Count - 1)
            zakazText += ", ";
    }

    TADOQuery *zakazQuery = new TADOQuery(NULL);
    zakazQuery->Connection = ADOConnection1;
    zakazQuery->SQL->Text = "INSERT INTO zakaz (price_, zak_, time_) VALUES (:price, :zak, :time)";
    zakazQuery->Parameters->ParamByName("price")->Value = totalSum;
    zakazQuery->Parameters->ParamByName("zak")->Value = zakazText;
    zakazQuery->Parameters->ParamByName("time")->Value = Now();
    try {
        zakazQuery->ExecSQL();
    } catch (const Exception& e) {
        ShowMessage("Ошибка при сохранении заказа в zakaz: " + e.Message);
    }
    delete zakazQuery;


    ListBox1->Items->Clear();
    LabelTotal->Caption = "Общая сумма: 0.00 руб.";
    EditQuantity->Text = "";
ComboBox1->Text = "";
}

void __fastcall TForm13::LoadUserInfo()
{
    TADOQuery *q = new TADOQuery(this);
    q->Connection = Form1->ADOConnection1;
    q->SQL->Text = "SELECT name_, lastname_, login_, number_, avatar_ FROM avtor WHERE id_ = :userID";
    q->Parameters->ParamByName("userID")->Value = Form1->UserID;
    try {
        q->Open();
        if (!q->Eof) {
            EditName->Text = q->FieldByName("name_")->AsString;
            EditLastname->Text = q->FieldByName("lastname_")->AsString;
            EditLogin->Text = q->FieldByName("login_")->AsString;
            EditNumber->Text = q->FieldByName("number_")->AsString;
            // Загрузка аватара
            avatarFilePath = q->FieldByName("avatar_")->AsString; // Сохраняем путь к аватару
            if (!avatarFilePath.IsEmpty() && FileExists(avatarFilePath)) {
                ImageAvatar->Picture->LoadFromFile(avatarFilePath); // Загружаем аватар
            } else {
                ImageAvatar->Picture->LoadFromFile("avatars\\5.jpg"); // Установка аватара по умолчанию
            }
        }
    } __finally {
        delete q;
    }
}
void __fastcall TForm13::ButtonLoadAvatarClick(TObject *Sender)
{
  std::unique_ptr<TOpenDialog> openDialog(new TOpenDialog(this));
    openDialog->Filter = "Image Files|*.jpg;*.jpeg;*.png;*.bmp";
    openDialog->Title = "Выберите аватар";

    if (openDialog->Execute()) {
        String selectedFilePath = openDialog->FileName;

        try {
            // Загружаем изображение в Picture напрямую
            ImageAvatar->Picture->LoadFromFile(selectedFilePath);

            // Подгоняем изображение по размеру компонента (масштабирование)
            ImageAvatar->Stretch = true;

            // Сохраняем путь
            avatarFilePath = selectedFilePath;
        }
        catch (const Exception &e) {
            ShowMessage("Ошибка при загрузке изображения: " + e.Message);
        }
}
}
